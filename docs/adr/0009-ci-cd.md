# ADR 0009: CI/CD with GitHub Actions and Workload Identity Federation

**Status:** Accepted

## Context
Until now every check ran on a laptop. A portfolio (and a team) needs every change proven
automatically, and deployments that don't depend on one person's machine - without
storing a cloud key in GitHub.

## Decisions
1. **Three workflows, three trust levels.**

   | Workflow | When | Cloud access | Does |
   |---|---|---|---|
   | `ci.yml` | every PR and push | **none** | pre-commit (ruff, YAML, private keys), pytest (incl. dbt parse, PII-tag and DQ coverage tests, workflow policy tests), sqlfluff, Airflow DAG integrity, `terraform fmt` + `validate` |
   | `terraform-plan.yml` | PRs touching `infra/` | `sa-cicd`: metadata read-only | posts the plan as a PR comment |
   | `deploy-dbt.yml` | after green CI on `main`, if dbt changed | `sa-transform` | Silver -> Gold -> DQ gate, same as Airflow |

2. **Workload Identity Federation, no keys.** GitHub issues a short-lived OIDC token per job;
   Google trusts only tokens from this repository (`attribute_condition`). Bindings:
   any workflow in the repo -> `sa-cicd`; only refs/heads/main -> `sa-transform`.
   A pull request therefore cannot write production tables, even if it edits a workflow.
3. **`sa-cicd` sees the shape of everything, the data of nothing.** Terraform plan needs to
   read every resource and its IAM policy. Basic Viewer would also grant read on every
   table (including raw PII in Bronze), so it gets metadata-only roles instead
   (`bigquery.metadataViewer`, `iam.securityReviewer`, `secretmanager.viewer`, ...), reads
   the state bucket, and plans with `-lock=false`.
4. **CI plans, humans apply.** Applying Terraform needs near-owner rights; giving those to
   CI would make the repo the weakest link. `make tf-apply` after reviewing the PR's plan.
5. **dbt is validated offline on PRs** (parse + sqlfluff + unit tests) rather than built in
   BigQuery. Building a PR in CI datasets would need read access to Bronze (raw PII) from
   PR code. With masked or synthetic CI sources, `dbt build --empty` into `ci_*` datasets
   is the next step.
6. **Policy as tests.** `tests/unit/test_workflows.py` fails the build if a workflow drops
   explicit token permissions, uses `pull_request_target`, a JSON key, an unpinned action,
   or lets pull requests act as the production identity.
7. **Dependabot** keeps actions, Python packages and the Terraform provider current through
   small PRs that go through the same CI.

## Consequences
- No secret is stored in GitHub; repository *variables* hold only non-secret ids.
- A merged dbt change reaches BigQuery in minutes without a laptop, and only if CI passed.
- A Terraform plan that hits a missing metadata permission fails loudly (403 names it).
- WIF pools are soft-deleted for 30 days: after `terraform destroy`, re-creating the same
  pool id fails until it is undeleted (`gcloud iam workload-identity-pools undelete`).
